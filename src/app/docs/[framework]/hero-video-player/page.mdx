# Hero Video Player

An embeddable, hardware-accelerated media hero for landing pages and high-conversion sections. Features a glassmorphism CTA, automatic dark/light mode responsiveness, and full keyboard accessibility.

Four independent components live on this page, and each installs on its own:

- **`HeroVideoPlayer`** — the poster hero. `playbackMode` opens the video in a **modal**, swaps it **inline** into the card, or renders it **directly** on load; `source` puts either a YouTube embed or a native HTML5 `<video>` behind it. No player library.
- **`HeroAudioPlayer`** — the same hero language for audio, with artwork, transport, scrubber and volume. No player library.
- **`HeroPlyrPlayer`** — [Plyr](https://plyr.io) driving HTML5 files, YouTube and Vimeo behind one skinnable control bar.
- **`HeroJwPlayer`** — [JW Player](https://jwplayer.com) with colour skin presets, for teams already on JW's platform.

Reach for the first two unless you need adaptive streaming, DRM or a shared control bar across providers — they add no player dependency at all.

## YouTube & native video

Click the CTA in any preview to start playback. In `modal` mode `Esc` closes the dialog and focus returns to the play button.

### JW Player setup

`HeroJwPlayer` has no npm dependency: JW ships a licensed library from its own CDN, and the component loads it at runtime.

1. Create a player in the [JW Dashboard](https://dashboard.jwplayer.com) and copy its cloud-hosted library URL — `https://cdn.jwplayer.com/libraries/<PLAYER_ID>.js`.
2. Pass it as `libraryUrl`. For a self-hosted build, also pass the `licenseKey` from your player settings.
3. Leave `libraryUrl` unset only while evaluating. The default is JW's public documentation library, which carries JW's branding and can be rotated or rate-limited without notice.

If the library fails to load, the component renders a native `<video>` with the poster and a visible warning rather than a black box — so a licence problem degrades instead of breaking the page.

## Best Practices & Guidelines

    <p className="text-blue-800 dark:text-blue-400/80 text-sm">Use <code>modal</code> above the fold, where the video is the page's main call to action. Use <code>inline</code> mid-page — an overlay that hijacks the whole viewport from a card the reader scrolled past reads as an interruption. Use <code>direct</code> when the video <em>is</em> the content, such as a documentation walkthrough.</p>
  </div>
  <div className="p-5 rounded-xl border border-amber-200 dark:border-amber-900/50 bg-amber-50/50 dark:bg-amber-950/20">
    <h4 className="text-base font-semibold text-amber-900 dark:text-amber-300 mb-1">Autoplay is a request, not a guarantee</h4>
    <p className="text-amber-800 dark:text-amber-400/80 text-sm">Browsers block autoplay with sound. <code>autoPlay</code> only applies to <code>playbackMode="direct"</code>, and the native player mutes itself when it is set. In <code>modal</code> and <code>inline</code> the click <em>is</em> the gesture, so playback starts on its own and the component adds <code>autoplay=1</code> to the embed URL for you.</p>
  </div>
  <div className="p-5 rounded-xl border border-emerald-200 dark:border-emerald-900/50 bg-emerald-50/50 dark:bg-emerald-950/20">
    <h4 className="text-base font-semibold text-emerald-900 dark:text-emerald-300 mb-1">Optimizing thumbnails</h4>
    <p className="text-emerald-800 dark:text-emerald-400/80 text-sm">Give <code>thumbnailUrl</code> a resolution that matches your <code>aspectRatio</code>. It is the poster, the LCP candidate and — for <code>source="video"</code> — the <code>&lt;video&gt;</code> element's own <code>poster</code>, so a mismatched crop shows up in all three places.</p>
  </div>
  <div className="p-5 rounded-xl border border-purple-200 dark:border-purple-900/50 bg-purple-50/50 dark:bg-purple-950/20">
    <h4 className="text-base font-semibold text-purple-900 dark:text-purple-300 mb-1">Choosing a backend</h4>
    <p className="text-purple-800 dark:text-purple-400/80 text-sm">Start with <code>HeroVideoPlayer</code> — it ships no player library. Move to Plyr when you need one consistent, skinnable control bar across YouTube, Vimeo and self-hosted files. Move to JW Player when you are already on JW's platform for adaptive streaming, DRM or analytics.</p>
  </div>
</div>
